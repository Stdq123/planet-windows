# v0.0.1-alpha.2 有限范围验收记录

维护者本次要求基于最新 `main` 重新打包并发布带新 Logo 的 Windows 安装包。`v0.0.1-alpha.1` 已公开，因此本次使用新版本 `v0.0.1-alpha.2`，不移动旧标签或替换旧版本附件。相对上一版，本次包含 Neighbor Pages 品牌资源、安装器及卸载器图标、侧栏标志、网页预览 favicon 和使用文档更新。

本次执行假设是延续已披露的**未签名预发布**策略与七个原生静默安装场景的有限验收范围。此范围仅适用于本次 `v0.0.1-alpha.2` 发布请求，不代表稳定版完整验收通过，也不是后续版本的默认豁免。所有未测项目保留如下；不能因变更主要是图标而跳过本次最终包测试。

本文件固定本次范围和证据要求，不预填尚未生成的最终包摘要、运行结果或自引用的最终提交 SHA。实际结果必须随本次 GitHub Release 附件发布。[alpha.1 历史记录](acceptance-0.0.1-alpha.1.md)保持原样，其运行链接、测试计数和包摘要不作为 alpha.2 的通过证据。

## 发布前必须重新通过的七个原生场景

使用一次性 Windows 虚拟机和合成资料。以下每项都必须由本次最终包的新结果证明；未执行或失败均不记为通过。

| 原生事件 | 本次要求 |
| --- | --- |
| `nonempty-directory-refused` | 拒绝含未知内容的目标目录，并保留内容 |
| `fresh-install-payload-registration-shortcut` | 验证新装文件、注册信息与快捷方式 |
| `installed-program-version` | 已安装程序的只读版本命令返回 `0.0.1-alpha.2` |
| `same-package-reinstall-no-op` | 同一安装包重装不改变已验证文件 |
| `locked-file-reinstall-and-uninstall-refused` | 文件锁定时拒绝重装和卸载，保留文件 |
| `tampered-file-reinstall-and-uninstall-refused` | 文件篡改时拒绝重装和卸载，保留现场 |
| `uninstall-descendants-complete-owned-files-removed-user-data-preserved` | 卸载及其子进程结束，自有文件移除，合成用户资料保留 |

新的运行即使使用同一工作流或 VM 镜像，也必须记录本次包的实际摘要。通过测试后重新构建导致摘要变化时，应测试新包，不能把旧证据附给新字节。

## 本次发布判定与附件

只有在最终提交的质量检查、安全扫描、构建、安装包审计、对应源码准备与重建验证以及上述七个原生场景均取得新的通过证据后，才按本次已披露范围发布未签名 alpha。任何失败仍须处理，不得引用 alpha.1 的通过结果绕过。完整适用验收与有效签名仍是稳定版要求。

最终 Release 必须标记为 pre-release，并保留 **UNSIGNED PRERELEASE** 提示。附件记录最终附注标签及提交、干净源码身份、实际安装包名称/大小/SHA-256、对应源码包及清单、本次质量与安全日志、原生运行链接和 JSON、`audit.json` 与 `SHA256SUMS.txt`，附带本文的未测试范围。最终摘要从实际文件产生，不回写当前源码提交。

全部五个内置模板继续保留来源、署名和已有许可文本，不重新设置模板待审门槛；Kubo 许可材料和包内摘要须按发布检查重新核对。许可材料收集不等于全面法律判断。签名服务的申请或等待状态不构成已签名证据；本次按未签名策略执行，未来接入以最终 Authenticode 验证为准。

没有配置生产 update feed，本次采用手动下载，生产 feed 地址、签名清单、到期时间与发布步骤不适用，不承诺自动更新。维护者负责核对附件、观察问题反馈并停止分发问题版本。

面向 alpha 使用者的限制：

- 安装包未签名，Windows 可能提示或阻止运行；核对发布的 SHA-256，不关闭系统防护。
- 原生安装覆盖仅限本次附件明确记录的七场景；Windows 10/11 GUI、WebView2、中文输入与新图标的实际桌面显示仍未完成完整验收。
- 在隔离的新 Windows 用户环境使用合成或可丢弃资料，保留原始备份；真实跨版本升级、断电恢复和 Mac 备份兼容尚未验证。
- 不覆盖已有 `0.2.0`/`0.3.0` 开发安装或用户资料；本次没有生产自动更新源，后续版本请手动下载。
