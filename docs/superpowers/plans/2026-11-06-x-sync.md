# X article sync

Base: local `main`, `7c95384`; branch: `feature/x-sync`.

## Scope and decisions

Publish a single X post containing the article title and canonical HTTPS permalink after a successful IPNS publication. Configuration is opt-in per site. Use OAuth 1.0a user credentials with write access and the existing Windows DPAPI configuration storage. OAuth2 PKCE would improve third-party onboarding but requires callback and token lifecycle work; a browser share intent cannot provide automatic sync. Four developer credentials are the chosen first implementation.

Automatic sync covers articles created after automatic sync is enabled. Existing articles can be sent explicitly after the current saved site revision is published. Drafts, pages, and imported sites are excluded. Editing or republishing a sent article never posts it again. Disabling removes credentials and retains send history. Changing credentials also retains history.

Persist a pending record before each request, then the returned post ID on success. Definite rejection becomes failed; timeout, malformed success, or server errors remain pending. No automatic retries. Manual retry of an uncertain request requires checking X first. X failure is a separate warning after successful site publication. Credentials and records remain outside public content and backups.

## Implementation

1. `windows/internal/services/x*.go` and `config.go`: OAuth signature and bounded fixed-endpoint client, conservative Unicode title length, protected credentials and per-article records. Verify known signature vector, rejection versus uncertain response, redirects, Unicode, invalid records and DPAPI round-trip.
2. `windows/x_sync.go`, `x_sync_test.go`, minimal `main.go` hooks: configure, disable, inspect, manual and automatic sync using the successful publication snapshot. Verify opt-in, no historical backfill, no duplicate, uncertain retry, publish gate, failure isolation, and credential-free responses. Regenerate `src/mygo.ts`.
3. `windows/src/x-sync.ts`, `index.html`, minimal `main.ts` wiring and frontend tests: existing modal style, masked credentials, automatic toggle, status list, explicit manual send/retry, clear credentials on save/close, prevent stale or concurrent actions.
4. Update usage docs and Unreleased changelog. Run `bun run check`, inspect changes independently, and test the rendered dialog where supported. No live posts or account charges during verification.

## Review focus

No publication before IPNS success; use only the captured published snapshot. Uncertain delivery survives restart. Record persistence failure must not trigger resend. Secret values never return to the frontend. Blank fields preserve all four existing credentials; partial credentials are rejected. Site deletion clears local X state. Limits and setup follow current official X documentation, with no pricing or quota constants.
