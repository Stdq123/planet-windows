# 升级与恢复

从 0.2.0 开始，正式构建的 Windows 程序和独立安装器使用事务协议 2。关闭 Planet，运行版本号更高的安装包，安装器会读取已登记的目录并在原位置升级。相同内容可重复运行；相同版本号但内容不同、降级、修改/缺少的自有文件、不可信登记、路径重解析以及文件集合变化均拒绝升级。从 0.3.0 可显式配置可信 HTTPS 更新清单和 Ed25519 公钥，启用启动检查并下载经过签名、时效、版本和 SHA-256 校验的安装包。默认未配置真实发布源，也不会静默执行安装包；需手动关闭 Planet 后运行。Ed25519 清单签名不等于 Windows Authenticode 签名，详见 [发布者说明](update-publisher.md)。

旧安全 0.1 和 MyGo 安装不包含整个运行期的事务锁，无法可靠参与新协议，因此不允许直接覆盖迁移。它们不因重新打包旧二进制而获得升级保障。`build-safe-installer.ps1` 是受信任开发者的打包工具，不证明任意外部 payload 实现了协议；正式发布必须使用当前项目生成、完成测试的程序。

## 中断恢复

安装器、卸载器和协议 2 程序共用运行期互斥对象。升级子进程验证真实父进程与创建时间，并复制父进程的原锁句柄，因此父安装器退出后仍保持排他。

升级先核对登记的 SHA-256，向私有注册表登记一份完整事务记录，再发布完整文件日志。新文件在同一卷的私有暂存目录写入、同步、验证；校验和移动原文件期间持续持有独占句柄。旧 exe 最先隔离，新 exe 最后放置。程序发现 `.planet-update` 时显示恢复提示，在读取用户资料前退出。重新运行同一安装包可继续完成；不同包不能接管该事务。注册信息更新后，以同一目录句柄归档日志来解除启动阻断。未知安装目录文件和用户资料不参与替换。

已完成的 `.planet-update-completed-*` 目录保留旧程序与恢复证据，不是资料库回滚入口。不要直接运行其中的旧二进制。未完成更新时也不允许卸载。磁盘损坏、第三方修改或暂存文件校验失败会保守停止；需保留日志和原文件进行人工恢复。上述机制和测试覆盖进程中断后的重试，不等于断电、缓存丢失或文件系统损坏恢复保证。

## 资料库格式

新版首次读取格式 1–3 的资料库时，先把原始 `library.json` 字节保存为私有 `library-before-v4-<SHA256>.json`，再一次性迁移至格式 4。快照通过同步临时文件、无覆盖发布生成；现有符号链接或内容冲突会被拒绝。旧 Windows 程序会拒绝格式 4，避免静默丢弃新字段。原始快照可能包含私有信息，只留在资料目录内。

后续增加资料字段或改变其含义时，开发者必须重新审查并提高资料格式版本，验证旧读者拒绝和迁移快照。保留旧 exe 不代表可以自动退回旧资料库；当前没有升级后继续编辑情况下的自动数据回滚。更新下载缓存位于用户资料目录的 updates 子目录；正常取消会只清理仍与已签名摘要一致的本次文件，无法确认身份的变更文件会保留并提示位置。异常断电或强制结束进程可能留下 .part 文件，它们不会被当作可安装的更新。

## 验证

原生 Go 测试覆盖文件切换各检查点中断和重试、注册提交前后恢复、伪造日志拒绝、旧协议/文件集合变化拒绝、全运行期锁、父子锁对象传递、快照与旧格式迁移。实际安装包还需运行禁网 Docker/Wine 的 `scripts/release-audit/test-transaction-upgrade.ps1`，用标记为 TEST-ONLY 的 0.3 夹具测试 0.2 → 0.3。该夹具不能分发。

Wine 不能代替原生 Windows 10/11 隔离虚拟机上的完整安装、升级、卸载、进程强杀和断电验收。程序与安装包未签名；正式对外分发前还需处理签名与依赖许可审查。
