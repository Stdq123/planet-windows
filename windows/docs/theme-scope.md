# 当前主题范围：仅浅色

记录日期：2026-11-06。适用于第二批视觉修复 P0-B 之后的应用界面；这是维护者明确选择的当前范围，不是深色主题的实现或验收记录。

## 范围决定与原因

当前沿用浅色侧栏、暖白工作区和石墨色控件。Windows 切换为深色模式时，应用外壳的 WebView 内容和文章阅读 iframe 仍保持浅色，不随系统切换为深色主题。编辑预览采用同一套浅色阅读样式。原生窗口标题栏由 Windows / MyGo 管理，不属于这套 WebView 调色板。

本轮先修复现有浅色界面的必要控件边界、文字对比度、状态语义和选中态线索，保留已经采用的桌面写作布局。完整深色主题还需要背景、文字、描边、强调色、状态色和阅读文档逐项映射，并单独验证每种状态；这些映射当前尚未实现。此范围决定不表示深色支持已经完成，也不豁免浅色界面的对比度、焦点或其他无障碍要求。

| 范围 | 当前行为与实现位置 |
| --- | --- |
| 导航、概览、编辑区、应用对话框 | 使用 [design-tokens.css](../src/design-tokens.css) 中的浅色语义角色，组件继续读取现有样式层叠；没有应用级深色 token 映射。 |
| 本地文章、订阅文章和编辑预览 | iframe 使用 [ui.ts](../src/ui.ts) 的 `readingStyles`，由 [main.ts](../src/main.ts) 和 [feed-reader.ts](../src/feed-reader.ts) 生成文档；宿主阅读区域保持浅色。尚未建立外壳与阅读文档的深色同步。 |
| 站点模板示例、生成的站点和外部网页 | 配色由各自模板或页面决定，不属于应用阅读主题的支持承诺；不能以某个模板自带深色样式推断应用支持深色。 |

## 强制颜色模式与验证边界

`forced-colors` 是用户选择的系统对比度配色机制，与通常的浅色/深色主题切换不同。现有样式包含使用 `Highlight`、`CanvasText` 等系统颜色的局部规则；它们不构成深色调色板，也不证明 Windows 高对比度验收已通过。

| 检查 | 当前状态 |
| --- | --- |
| 应用深色 token、阅读文档深色映射及其对比度 | 未实现；按本轮仅浅色范围不适用，不能记为测试通过。 |
| Windows 浅色/深色切换时外壳与阅读 iframe 的实际表现 | 未实机验证；当前代码预期均保持浅色。 |
| WebView2 中的焦点、控件边界、选中态与阅读区域 | 未实机验证。 |
| Windows 高对比度模式下的完整交互与状态 | 未实机验证；浏览器 `forced-colors` 模拟不能替代。 |
| Narrator 实际朗读、200% 缩放下的布局与焦点 | 未实机验证。 |

后续引入深色主题时，需要同时更新外壳和阅读文档的语义映射，重新验证浅色、深色及系统强制颜色模式，并同步 [发行检查范围](release-audit.md#当前主题检查范围)。本记录不改变已有发行包的历史验收结果。
